# Composition for substantial visual explanations

## Decide what deserves a figure

A visual should make a relationship easier to understand than prose alone. Build from the actual subject: interfaces, artifacts, stages, connections, quantities, or visible differences. Use short text where text is best; do not decorate every fact with a diagram or turn a category list into a fake process.

Pick the main distinction, then supporting evidence. Consider alternative arrangements before implementation: a matched workflow may explain a tool comparison better than a feature matrix; an overview with enlarged details may explain an interface better than two full-window thumbnails. Choose based on the question, not a fixed template.

## Screenshots that explain

- Inspect authentic screenshots and select relevant application states. Where possible, compare similar tasks or views. A busy editor versus an empty welcome screen is weak evidence of workflow differences; find a representative task view or limit the comparison to what the images actually show.
- Preserve enough interface context to recognize each product. Enlarge important regions separately when full-window text would be unreadable. Do not crop out differences that matter or alter the underlying UI.
- Add a few precise callouts outside the image, linked to visible controls, panels, or results. Keep leader lines short and away from text. Number callouts only when they map to actual numbered notes or a sequence.
- Annotations should explain specific visible functions, not merely repeat product names or claim unsupported capabilities. Use working source links in the HTML or concise citations in the accompanying chat when external research requires them; avoid long provenance captions on the image.
- If only a marketing screenshot or a welcome screen is available, do not invent a realistic-looking UI to fill the gap. Use a clearly schematic workflow for researched behavior and keep it distinct from the actual screenshot.

## Choose useful structures

- **Interface comparison:** paired overview images with aligned labels, then enlarged regions for the important differences. Let the reader inspect the relevant controls without zooming the entire export.
- **Workflow comparison:** show the same user task in parallel lanes. Label real actions and outputs; highlight where the paths differ. Use arrows only where there is a genuine progression or dependency.
- **Scope comparison:** group concrete capabilities by task, showing overlap and distinct coverage. Do not equate an unverified feature with absence or invent numerical scores for qualitative traits.
- **Mechanism:** show the components and their actual interactions. Label connections with the action, rather than linking vague boxes with unlabeled arrows.
- **Precise comparison:** use a compact matrix for facts such as platform, access, or formats. Prefer short cell text. Let it support the main figures when the request is broader than lookup.

Combine only the structures that add understanding. A rich explanation might use annotated screenshots and one matched workflow, with a small facts strip. It does not need every section above, a recommendation, or an invented winner.

## Example: two software applications

For a request to compare two apps and include screenshots, first establish their relevant use cases from reliable sources. Select screenshots that reveal those use cases. Place the two views on a shared alignment, enlarge the panels that matter, and label the visible differences. If the products organize the same task differently, draw that task in matched lanes beneath or beside the screenshots. Reserve a small table for remaining exact facts. Keep the title to the product names; no slogan or repeated descriptive subtitle.

This is a composition example, not a prescribed claim about any particular product. Do not borrow facts from an earlier comparison without checking them.

## Finish at the intended viewing size

Inspect the image at its expected display width, not only at full export resolution. Read annotations without zooming. Check that the focal point is clear, connected details remain close, and screenshot callouts land on the right controls. If the evidence is too small, enlarge or split the composition rather than shrinking the labels. For multiple images, each must stand on its own while maintaining consistent product colors and alignment.

Before delivery, ask whether the visual teaches something that a plain table would not. If not, and the task needs explanation rather than lookup, revise the figures. Preserve plain titles and concise copy throughout; visual depth comes from meaningful structure and detail, not extra prose or decoration.
